7. PDF FORMATTING PRESERVED IN AUTO-FILL (user feedback: "text was uploaded but none of the formatting was used"; commit 44272ad)
- Cause: the extractor used plain text only, so every line became a <p>.
- Now reads per-glyph font, size and position (pdf.Page.Content) and rebuilds: h1/h2/h3 headings, <strong>/<em> runs, wrapped paragraphs and wrapped bullets joined back together. New file internal/resumeextract/pdf_layout.go.
- Heading rules: size >= 1.6x body -> h1; >= 1.25x -> h2; bold ALL-CAPS short line -> h2; bold and >= 1.1x -> h3. Body size = most common size by character count.
- Paragraph lines are merged only when the previous line visibly ran to the right margin (>= 85% of page text width) with no big internal gap (right-aligned dates), same left edge and same boldness. Short standalone lines (name, title, contact, "Company    dates") therefore stay separate.
- Bullet continuation lines (indented past the marker) are joined into the same list item.
- Word gaps with no space glyph (common in word-processor PDFs) are turned into spaces using glyph X/width.
- Bold/italic is inferred from the font name (Bold/Black/Heavy/Demi, Italic/Oblique). More bullet glyphs recognised (private-use Symbol bullets, square/circle bullets, en dash).
- Falls back to the old plain-text path if the styled read fails or is empty.
- Library note: this library's Content() panics on malformed streams, so it is wrapped in recover. Fonts without /Widths do not advance X, so the test fixture supplies widths like real PDFs do.
- DOCX still has no bold/italic (not requested).
- Known limits: multi-column layouts interleave; scanned/image-only PDFs give no text; thresholds are heuristics tuned on a synthetic PDF plus the user's own real-resume test.

8. PROFILE DELETION (post-spec addition requested by user; commit 416aa21)
- Candidates can delete their own profile; admins can delete candidates, companies (employers) and jobs.
- Mechanism: delete the owning users row (UserRepo.Delete) and rely on the existing ON DELETE CASCADE foreign keys (candidate/employer, jobs, files, votes, messages, sessions, reset tokens). No new migration.
- UserRepo.Delete refuses admin users (role <> 'admin'), returning ErrNotFound.
- Deleting a candidate/company also removes the counterpart's copy of message threads with them (cascade on sender/recipient) - accepted consequence, documented in README.
- Deleting a company deletes all its jobs. Deleting a single job leaves the company.
- Stored uploads (photo, logo, candidate files) are not covered by the DB: keys are collected first and deleted best-effort AFTER the DB delete. A storage failure leaves an orphaned file, never a half-deleted account.
- Candidate self-delete: POST /candidates/{slug}/delete, RequireRole(candidate) + ownership check + CSRF + password re-entry (irreversible action; a stolen session should not be enough). Wrong password re-renders the edit page with a 422 error. Success clears the session cookie and redirects to /.
- Admin delete: POST /admin/{candidates,employers,jobs}/{id}/delete behind RequireAdmin + CSRF; buttons on the admin list pages with a browser confirm() prompt. No CSP is set, so inline onsubmit works.
- Logic lives in internal/web/account_delete.go as free functions over *app.App so candidate and admin handlers share it.
- Employer self-delete was NOT requested and is not implemented.
- The hourly search_index materialized view may list a deleted profile until its next refresh; live search, pages and sitemap read base tables, so they are correct immediately.
- README has a new "Notable profile-deletion decisions" section.
- Tests (internal/web/account_delete_test.go, DB-gated): wrong password keeps account; correct password deletes user/candidate/session/stored file; cannot delete another candidate (403); admin deletes candidate, job, employer (jobs cascade); non-admin cannot use admin delete; admins are never deletable.
